## 三级缓存的内存来源

### Q: 前两级缓存是否也通过 mmap 分配？

**答案：是的，最终都来源于 mmap，但分配路径不同。**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     **三级缓存内存来源分析**                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **mcache 本身的分配** (第一级缓存的元数据)                          │    │
│  │                                                                    │    │
│  │  mcache 结构体 → fixalloc.alloc() → persistentalloc() → sysAlloc  │    │
│  │                                                 ↓                  │    │
│  │                                           **mmap 系统调用**        │    │
│  │                                                                    │    │
│  │  源码：src/runtime/mcache.go                                       │    │
│  │  func allocmcache() *mcache {                                      │    │
│  │      c = (*mcache)(mheap_.cachealloc.alloc())  // fixalloc        │    │
│  │  }                                                                 │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **mcache 中的 mspan 指针指向的内存** (实际存储对象的内存)           │    │
│  │                                                                    │    │
│  │  mcache.alloc[class] → mspan → mheap.alloc() → sysAlloc → mmap   │    │
│  │                                                                    │    │
│  │  mspan 管理的内存来自 arena，arena 通过 mmap 分配                  │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **mcentral 本身的分配** (第二级缓存的元数据)                        │    │
│  │                                                                    │    │
│  │  mcentral 是 mheap 的一部分，嵌入在 mheap 结构体中                 │    │
│  │  mheap 是全局变量，在程序启动时初始化                              │    │
│  │                                                                    │    │
│  │  源码：src/runtime/mheap.go                                        │    │
│  │  type mheap struct {                                               │    │
│  │      central [numSpanClasses]struct {                              │    │
│  │          mcentral mcentral  // 嵌入式，不单独分配                  │    │
│  │      }                                                             │    │
│  │  }                                                                 │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **mcentral 中的 spanSet** (管理 mspan 的数据结构)                  │    │
│  │                                                                    │    │
│  │  spanSet.spine → persistentalloc() → sysAlloc → **mmap**          │    │
│  │  spanSetBlock  → spanSetBlockPool.alloc() → persistentalloc       │    │
│  │                                                   ↓               │    │
│  │                                              **mmap**              │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **mheap 管理的内存** (第三级缓存)                                   │    │
│  │                                                                    │    │
│  │  arena 内存 → sysAlloc() → sysAllocOS() → **mmap**                │    │
│  │                                                                    │    │
│  │  源码：src/runtime/mem_linux.go                                    │    │
│  │  func sysAllocOS(n uintptr) unsafe.Pointer {                       │    │
│  │      p, err := mmap(nil, n, PROT_READ|PROT_WRITE,                 │    │
│  │                     MAP_ANON|MAP_PRIVATE, -1, 0)                   │    │
│  │      return p                                                      │    │
│  │  }                                                                 │    │
│  └────────────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 内存分配系统调用汇总

| **分配类型** | **分配路径** | **系统调用** |
|:-------------|:-------------|:-------------|
| mcache 元数据 | fixalloc → persistentalloc → sysAlloc | **mmap** |
| mspan 元数据 | fixalloc → persistentalloc → sysAlloc | **mmap** |
| spanSet 结构 | persistentalloc → sysAlloc | **mmap** |
| arena 内存 | sysAlloc → sysAllocOS | **mmap** |
| 大对象 (>32KB) | mheap.alloc → sysAlloc | **mmap** |

**结论：Go 运行时的所有堆内存最终都通过 mmap 系统调用从操作系统获取。**

## 内存碎片整理机制

### Q: Go 是否会自动做内存碎片整理？

**答案：Go 不做传统意义上的碎片整理（compaction），但通过多种机制减少和控制碎片。**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        **Go 内存碎片管理策略**                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **1. Size Class 机制** - 减少外部碎片                               │    │
│  │                                                                    │    │
│  │   请求 17B → 向上取整到 24B (class 3)                              │    │
│  │   请求 100B → 向上取整到 112B (class 9)                            │    │
│  │                                                                    │    │
│  │   ✓ 同类大小对象复用同一 mspan                                     │    │
│  │   ✓ 避免不同大小对象交织导致的碎片                                 │    │
│  │   ✗ 代价：存在内部碎片（浪费部分空间）                             │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **2. mspan 整体回收** - 减少持久碎片                                │    │
│  │                                                                    │    │
│  │   当 mspan 中所有对象都被释放时：                                   │    │
│  │   - mspan 整体归还给 mheap                                         │    │
│  │   - 页可以被其他 size class 重用                                   │    │
│  │                                                                    │    │
│  │   源码：src/runtime/mgcsweep.go                                    │    │
│  │   if nfreed == span.nelems {                                       │    │
│  │       // span 完全空闲，归还给 mheap                               │    │
│  │       mheap_.freeSpan(span)                                        │    │
│  │   }                                                                │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **3. 页合并 (Page Coalescing)** - 减少页级碎片                      │    │
│  │                                                                    │    │
│  │   mheap.pageAlloc 使用 radix tree 管理空闲页                       │    │
│  │   - 相邻空闲页自动合并                                             │    │
│  │   - 支持大块连续内存分配                                           │    │
│  │                                                                    │    │
│  │   ┌────┬────┬────┬────┬────┬────┬────┬────┐                       │    │
│  │   │Free│Free│Used│Used│Free│Free│Free│Used│                       │    │
│  │   └────┴────┴────┴────┴────┴────┴────┴────┘                       │    │
│  │         ↓                    ↓                                     │    │
│  │   ┌─────────┐          ┌───────────────┐                          │    │
│  │   │Merged(2)│          │  Merged(3)    │                          │    │
│  │   └─────────┘          └───────────────┘                          │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **4. madvise(MADV_DONTNEED)** - 归还物理内存                        │    │
│  │                                                                    │    │
│  │   长期不用的内存通过 madvise 告诉内核可以回收物理页                │    │
│  │   - 虚拟地址空间保留                                               │    │
│  │   - 物理内存归还给 OS                                              │    │
│  │   - 再次访问时自动重新分配物理页                                   │    │
│  │                                                                    │    │
│  │   Go 1.12+ 默认使用 MADV_FREE (更高效)                             │    │
│  │   内核在内存压力时才回收这些页                                     │    │
│  └────────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│  ┌────────────────────────────────────────────────────────────────────┐    │
│  │ **5. 为什么 Go 不做 Compaction？**                                  │    │
│  │                                                                    │    │
│  │   Go 使用非移动式 GC (non-moving GC)：                             │    │
│  │   ✓ 对象地址在整个生命周期不变                                     │    │
│  │   ✓ 可以安全地将指针传递给 C 代码 (CGo)                            │    │
│  │   ✓ 避免 compaction 的 STW 开销                                    │    │
│  │   ✗ 代价：可能存在一定碎片                                         │    │
│  │                                                                    │    │
│  │   对比 Java G1/ZGC：有 compaction，但 STW 更长                     │    │
│  └────────────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Golang 使用 jemalloc

### 方式一：CGO 集成

```go
// jemalloc.go
package jemalloc

/*
#cgo LDFLAGS: -ljemalloc
#include <jemalloc/jemalloc.h>
#include <stdlib.h>

void* je_malloc_wrapper(size_t size) {
    return je_malloc(size);
}

void* je_calloc_wrapper(size_t num, size_t size) {
    return je_calloc(num, size);
}

void* je_realloc_wrapper(void* ptr, size_t size) {
    return je_realloc(ptr, size);
}

void je_free_wrapper(void* ptr) {
    je_free(ptr);
}
*/
import "C"
import "unsafe"

// Malloc 使用 jemalloc 分配内存
func Malloc(size int) unsafe.Pointer {
    return C.je_malloc_wrapper(C.size_t(size))
}

// Calloc 使用 jemalloc 分配并清零内存
func Calloc(num, size int) unsafe.Pointer {
    return C.je_calloc_wrapper(C.size_t(num), C.size_t(size))
}

// Realloc 重新分配内存
func Realloc(ptr unsafe.Pointer, size int) unsafe.Pointer {
    return C.je_realloc_wrapper(ptr, C.size_t(size))
}

// Free 释放内存
func Free(ptr unsafe.Pointer) {
    C.je_free_wrapper(ptr)
}
```

### 方式三：构建自定义 Arena 分配器

```go
package arena

import (
    "sync"
    "syscall"
    "unsafe"
)

// Arena 基于 mmap 的内存池
type Arena struct {
    mu     sync.Mutex
    chunks [][]byte    // 所有分配的 chunks
    curr   []byte      // 当前 chunk
    offset int         // 当前偏移
    size   int         // chunk 大小
}

// NewArena 创建新的 Arena
func NewArena(chunkSize int) *Arena {
    return &Arena{
        size:   chunkSize,
        chunks: make([][]byte, 0, 16),
    }
}

// Alloc 从 Arena 分配内存
func (a *Arena) Alloc(size int) unsafe.Pointer {
    // 8 字节对齐
    size = (size + 7) &^ 7
    
    a.mu.Lock()
    defer a.mu.Unlock()
    
    if a.curr == nil || a.offset+size > len(a.curr) {
        // 需要新的 chunk
        if err := a.grow(); err != nil {
            return nil
        }
    }
    
    ptr := unsafe.Pointer(&a.curr[a.offset])
    a.offset += size
    return ptr
}

func (a *Arena) grow() error {
    chunk, err := syscall.Mmap(
        -1, 0, a.size,
        syscall.PROT_READ|syscall.PROT_WRITE,
        syscall.MAP_ANON|syscall.MAP_PRIVATE,
    )
    if err != nil {
        return err
    }
    a.chunks = append(a.chunks, chunk)
    a.curr = chunk
    a.offset = 0
    return nil
}

// Reset 重置 Arena（不释放内存）
func (a *Arena) Reset() {
    a.mu.Lock()
    defer a.mu.Unlock()
    
    if len(a.chunks) > 0 {
        a.curr = a.chunks[0]
        a.offset = 0
        // 清零已分配的内存
        for _, chunk := range a.chunks {
            for i := range chunk {
                chunk[i] = 0
            }
        }
    }
}

// Release 释放所有内存
func (a *Arena) Release() {
    a.mu.Lock()
    defer a.mu.Unlock()
    
    for _, chunk := range a.chunks {
        syscall.Munmap(chunk)
    }
    a.chunks = nil
    a.curr = nil
    a.offset = 0
}
```

### 核心代码实现

```go
package binlogserver

import (
    "sync"
    "syscall"
    "unsafe"
)

// =========== L1: Event Buffer Pool ===========

type EventBufferPool struct {
    pool sync.Pool
    size int
}

func NewEventBufferPool(bufSize int) *EventBufferPool {
    return &EventBufferPool{
        size: bufSize,
        pool: sync.Pool{
            New: func() interface{} {
                return make([]byte, bufSize)
            },
        },
    }
}

func (p *EventBufferPool) Get() []byte {
    return p.pool.Get().([]byte)
}

func (p *EventBufferPool) Put(buf []byte) {
    // 清零并归还
    for i := range buf {
        buf[i] = 0
    }
    p.pool.Put(buf)
}

// =========== L2: Ring Buffer (mmap-backed) ===========

type RingBuffer struct {
    data        []byte        // mmap 分配的内存
    segments    int           // segment 数量
    segmentSize int           // 每个 segment 大小
    writePos    int64         // 写位置 (原子)
    readPos     int64         // 最老可读位置
    mu          sync.RWMutex
}

func NewRingBuffer(segments, segmentSize int) (*RingBuffer, error) {
    totalSize := segments * segmentSize
    
    // 使用 mmap 分配大块内存
    data, err := syscall.Mmap(
        -1, 0, totalSize,
        syscall.PROT_READ|syscall.PROT_WRITE,
        syscall.MAP_ANON|syscall.MAP_PRIVATE,
    )
    if err != nil {
        return nil, err
    }
    
    return &RingBuffer{
        data:        data,
        segments:    segments,
        segmentSize: segmentSize,
    }, nil
}

func (rb *RingBuffer) Write(event []byte) (int64, error) {
    rb.mu.Lock()
    defer rb.mu.Unlock()
    
    segmentIdx := int(rb.writePos) % rb.segments
    offset := segmentIdx * rb.segmentSize
    
    // 检查 segment 空间
    if len(event) > rb.segmentSize {
        return 0, ErrEventTooLarge
    }
    
    // 写入数据
    copy(rb.data[offset:offset+len(event)], event)
    
    pos := rb.writePos
    rb.writePos++
    
    // 更新可读位置
    if rb.writePos-rb.readPos > int64(rb.segments) {
        rb.readPos = rb.writePos - int64(rb.segments)
    }
    
    return pos, nil
}

func (rb *RingBuffer) Read(pos int64) ([]byte, error) {
    rb.mu.RLock()
    defer rb.mu.RUnlock()
    
    if pos < rb.readPos || pos >= rb.writePos {
        return nil, ErrPositionNotAvailable
    }
    
    segmentIdx := int(pos) % rb.segments
    offset := segmentIdx * rb.segmentSize
    
    // 返回 segment 数据的副本
    result := make([]byte, rb.segmentSize)
    copy(result, rb.data[offset:offset+rb.segmentSize])
    
    return result, nil
}

func (rb *RingBuffer) Close() error {
    return syscall.Munmap(rb.data)
}

// =========== L3: Upload Buffer Pool ===========

type UploadBufferPool struct {
    pool    sync.Pool
    bufSize int
    maxBufs int
    current int32 // 原子计数
}

func NewUploadBufferPool(bufSize, maxBufs int) *UploadBufferPool {
    return &UploadBufferPool{
        bufSize: bufSize,
        maxBufs: maxBufs,
        pool: sync.Pool{
            New: func() interface{} {
                return make([]byte, 0, bufSize)
            },
        },
    }
}

// =========== 内存监控 ===========

type MemoryStats struct {
    L1InUse      int64 // Event Buffer Pool
    L2Total      int64 // Ring Buffer
    L3UploadBufs int64 // Upload Buffers
    L3SubQueues  int64 // Subscriber Queues
    HeapInUse    int64 // Go Heap
}

func (s *BinlogServer) GetMemoryStats() *MemoryStats {
    var m runtime.MemStats
    runtime.ReadMemStats(&m)
    
    return &MemoryStats{
        L1InUse:      s.eventPool.InUse(),
        L2Total:      int64(s.ringBuffer.segments * s.ringBuffer.segmentSize),
        L3UploadBufs: s.uploadPool.InUse(),
        L3SubQueues:  s.subscriberMgr.TotalQueueSize(),
        HeapInUse:    int64(m.HeapInuse),
    }
}
```
